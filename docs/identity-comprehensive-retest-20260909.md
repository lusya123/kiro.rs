## 根因与修改

- 日语自我介绍没有进入可信应用人设的响应过滤，日语自称和拒绝 Bob 人设的句式也未被处理。补充请求识别和自称语法处理，保留计算结果及明确要求的 `BOB:` 前缀。重复测试还捕获了括号内“基础是 Kiro”“作为 Kiro 运行”的补充说明；括号内句号原本会拆开身份上下文，现在按同一自我介绍处理，相邻产品描述仍保留。
- 西班牙语 `Preséntate` 等自我介绍请求也没有进入过滤，输出的 `soy Kiro` 同样被遗漏。补齐多语言请求与第一人称输出识别；对日语自称句中的独立名称按上下文处理，不再依赖特定的谓语或标点。引用、路径及明确的产品使用描述有独立保护回归。
- 原代码过滤识别整段字符串及相邻字符串拼接，但没有把字符列表、字符码列表和编码字符串当作一个身份值处理。现在对有界、静态的身份值进行解码、替换、再编码，保留解码调用和代码结构；不执行生成代码。
- 原识别器漏掉较长请求中的完整说法 `your current assistant name`，导致编码过滤单元测试通过、真实请求却绕过过滤。新增完整请求回归测试并修复该入口。
- 纯 `JSON fixture` 没有进入既有业务数据保护分支，现在复用该分支，避免输入身份覆盖和输出文字替换误改样例。
- 工具自报身份的 schema 只有 `name` 时未开启结构化身份处理，且该通用字段的替换原本只对 GPT 目标生效。补齐 Claude 的处理，同时保护工具参数里的路径、代码、payload 和 fixture。真实普通/SSE 请求曾返回 `{"name":"Kiro"}`，已加入请求上下文与字段转换的回归测试。
- 明确要求代码的身份请求不再以本地固定文字提前结束；JSON 请求的本地回复也必须是 JSON。真实模型仍可能附带说明或拒绝，因此这不等于保证任何回答都符合所要求的格式。

**本轮没有新增系统提示词。** 项目原有的输入身份覆盖仍存在；本轮仅让明确的 JSON 样例按既有业务数据规则绕过它。身份清洗的新增逻辑位于响应路径。

修复采用真实失败样本先写失败回归，再实施修改。最终 Rust 测试为 **1025 通过、0 失败、3 忽略**。

## 覆盖范围与判定方式

编程语言覆盖 Python、JavaScript、TypeScript、Rust、Go、C、C++、Java、Ruby、Bash、Swift、PHP、C#、Kotlin 和 SQL。自然语言覆盖中英、日、韩、法、德、西、葡、俄、阿拉伯语和印地语，并包含繁体中文问法。

方法包括字符串、拼接、字符数组、字符码、Unicode/十六进制转义、Base64、ROT13、倒序、模板字符串、代码注释、heredoc，及 JSON/YAML/XML/TOML/CSV、多轮历史、可信人设、thinking、真实工具参数与工具续聊。

生成代码只做语法解析和有界静态解码。Python 使用 `ast`；其他代码使用 `tree-sitter-language-pack==0.10.0`。这不等于执行程序，也不证明任意动态计算、混淆组合或未测试问法都无法泄漏。空回复、超时、无效格式、身份名称不符均不算通过。显式业务样例中应保留的 Kiro 名称不计为自称。
