# 格式与 Base64 截断复测（2026-09-09）

在指定 Worktree 中，以已发布提交 `5b95e8cd` 为基线继续排查。用户新提供的 13 个账号中，仅将第 1 个导入本地隔离测试服务 `127.0.0.1:62000`；实际调用确认 Opus 5、Opus 4.8 均可用。原始附件未修改，凭证与运行配置均位于 Git 忽略目录。

## 捕获到的原因

基线两批共 24 个真实请求中，22 个通过，两个失败：

- Opus 4.8 的 JSON 十六进制字段为 `436c60756465`，解码结果不是正确的助手名称。上游事件内容、本地格式处理前内容和客户端响应中的错误一致。
- Opus 4.8 的 Python Base64 输出停在 `print(base64.b64decode("Q2x`，字符串、括号和代码围栏均未结束。上游事件中的文本已经截断，随后只出现上下文用量事件，没有计量事件、完成状态或其他结束证据。相邻成功请求有计量事件。

第二个响应在一个完整 EventStream 帧的边界上结束，因此旧代码的“残留半帧”检查没有发现异常，最终错误地返回 HTTP 200 与 `end_turn`。证据只能说明上游返回不完整以及本地误判完成，不能确定上游内部停止的原因。

## 修改

- 为 AWS-B 的 Opus 5 / Opus 4.8 增加独立于 HTTP EOF、缓存资格的完成检查。非流式请求缺少结束证据时返回 502；已开始的 SSE 输出错误事件，不再发送正常的 `message_stop`。每轮续写分别检查。上游错误事件及残留半帧也返回失败，不再把它们包装成成功或普通 token 截断。
- 已缓冲的身份格式请求最多重试一次，沿用原模型、原输入和原 token 上限。包含工具定义、工具选择或工具历史的请求不重试；明确的拒绝、token 上限和停止序列保留原有终止语义。
- 对明确要求单一 JSON / 代码输出的身份请求检查文档及围栏完整性；对已识别的静态 Base64 / 十六进制姓名值校验解码结果。错误结果重试后仍不合格则返回 502，不补造缺失字符，不自动修正任意业务数据。
- 多语言实测另外发现一个 PHP 格式失败样本。请求识别确实遗漏了使用 `program` 而非 `code` 的部分语言，已补充 `program/script` 并覆盖 15 种语言。该 PHP 样本没有抓取上游边界，因此不将其畸形字符归因于某一具体层。

没有添加系统提示词，没有修改签名、ID 或用量字段的生成规则。定位期间使用的原始事件日志代码已移除。
